Starr installer

Install Starr apps on a Linux server with Docker. Start guided setup in the terminal, or build a custom command below.

Guided setup

curl -fsSL https://starr.danteb.com/i | sudo sh

Type this one-line command on the server. The installer asks about storage, applications, VPN and updates. Settings below do not change this command.

Requires curl, Python 3.10+, Docker Engine and Compose v2. The sh wrapper starts the Python installer. Already root? Omit sudo. Review the source before running downloaded code as root.

01

Requirements

System requirements

Install Python 3.10+, rootful Docker Engine, and Compose v2. You need sudo access. The installer does not install Docker or change your firewall.

Content storage

Mount your disk first. Downloads and libraries share a single /data mount so hardlinks and atomic imports work. Existing media is not reorganized or recursively chowned.

Accounts

Use your indexer and tracker accounts, plus VPN or Usenet accounts if selected. Complete app account setup after installation.

Account setup instructions →
Configured automatically
  • Starr root folders, qBittorrent categories and client connections, hardlinks, and torrent-first download preferences.
  • Prowlarr connections to Radarr, Sonarr and Lidarr, plus a flaresolverr tag and a proxy restricted to that tag. Apply it only to indexers that need FlareSolverr.
  • A public Internet Archive torrent indexer with a browser User-Agent, without FlareSolverr. Archive contains mixed-rights material; results are not filtered by license. Download only public-domain, openly licensed or otherwise authorized content.
  • Bazarr connections to Radarr/Sonarr, the Whisper endpoint and provider, and a subtitle profile if a language is selected below.
  • When profile sync is enabled: all 30 Recyclarr profiles per video app, custom formats, naming and size limits, followed by daily syncs.
  • Lidarr's FLAC-only profile and album/track naming, with audio-tag rewriting disabled to protect seeding hardlinks.
  • Jellyfin's initial administrator and movie, TV and music libraries. Plex libraries after the owner's account claim.
  • Starr Connect entries to refresh configured Plex/Jellyfin libraries after imports, upgrades and renames.
  • Seerr's Starr connections, root folders, request profiles and media libraries. Plex is the default when both media servers are selected. Missing account credentials are reported as deferred.
  • SABnzbd's provider and Starr clients when credentials are supplied and NNTP/client tests pass; otherwise the clients remain disabled.

Starr administrator accounts, indexer credentials and account-bound Plex/Usenet/Soulseek credentials still require your input. No account credentials are copied from the homeserver.

02

Installation settings

Settings are not uploaded, saved, or added to the URL. Enter paths to files on the Linux server, not passwords, API keys, or VPN profile contents.

Storage & users

Run id your-media-user on the server to find its UID/GID. Root is not a valid media user.

Optional applications
Media server & requests

Fresh Jellyfin uses the generated username/password in root-only state.json. Existing completed setups and later UI changes are preserved. Plex sign-in is required even when Seerr's Starr connections are preconfigured.

Usenet provider

JSON fields: host, username, password; optional port (563), ssl (true), connections (20). Use chmod 600. The installer tests the provided and saved NNTP settings before enabling SABnzbd in Starr. Without credentials, its clients stay disabled.

Subtitles

Creates a language profile and makes it the default for new series/movies unless defaults already exist. Whisper is enabled automatically; CPU transcription can be slow. Language and provider preferences can be changed later in Bazarr.

Torrent VPN
Soulseek account & separate VPN

Use a second tunnel/profile with a distinct WireGuard key. One forwarded port cannot serve both downloaders.

Access & maintenance

Keep loopback during onboarding and use an SSH tunnel. A LAN bind is not authentication. Never forward these web ports to the internet; Docker publishing can bypass UFW.

The proxy uses the same bind address as the apps. It does not publish anything on port 443 or request certificates. Finish app authentication before allowing LAN access.

How to run

All entry points require Python 3.10+. The shell wrappers check for Python and run it; they do not install it. Both download styles execute immediately. Use the source links to inspect the code first.

Guided mode still asks for direct-traffic consent and any unsupplied credentials. Unattended mode adds --non-interactive --yes; review the full command before running as root.

After installation

Application links

Based on the settings above; these links do not check whether installation is complete. Loopback addresses require SSH forwarding on this computer. A server hostname must already resolve on your network.

    Local proxy names and DNS

    Landing page: . It includes these app icons and direct fallback links.

    Map the following names in each client's hosts file, or create equivalent local DNS records. Replace SERVER_LAN_IPV4 with the server's LAN address if shown. Use 127.0.0.1 only on a client forwarding the proxy port over SSH. Hosts files cannot use wildcard names.

    
          
    Hosts files: /etc/hosts on Linux/macOS; C:\Windows\System32\drivers\etc\hosts on Windows (administrator access required). Caddy does not supply DNS. Router DNS changes may cause a reboot or network outage; make them during a low-usage window.
    
          
    The installer also writes <install-dir>/access/index.html and access/hosts.txt. With proxy port 8088 and the default loopback bind, use ssh -N -L 8088:127.0.0.1:8088 user@server and map the names to 127.0.0.1 on your computer.

    SSH access
    With the default loopback bind, forward the web ports from your computer over SSH. Substitute your server's SSH user/host (and add -p PORT if needed).
    ssh -N -L 7878:127.0.0.1:7878 \
  -L 8989:127.0.0.1:8989 \
  -L 8686:127.0.0.1:8686 \
  -L 9696:127.0.0.1:9696 \
  -L 8080:127.0.0.1:8080 \
  -L 6767:127.0.0.1:6767 user@server
    Then open, for example, http://127.0.0.1:7878 locally. Extra ports: SABnzbd 8085, slskd 5030, Plex 32400, Jellyfin 8096, Seerr 5055.
    
        
    Application setup
    1. Create the Starr administrator accounts before exposing any UI.
    2. Read generated credentials from <install-dir>/state.json with sudo. Keep it private. Fresh Jellyfin uses these for its administrator.
    3. Internet Archive is preconfigured. Add other authorized indexers in Prowlarr. Test its app connections; apply flaresolverr only where needed, not to Archive.
    4. Set up Bazarr authentication and any additional subtitle-provider accounts. Check the configured language profile and Whisper connection.
    5. Complete any explicitly deferred Plex, Usenet or Soulseek account setup and rerun the installer. Seerr's server, profiles and libraries are configured once its media-server authentication succeeds.
    6. Check Seerr's request profiles, test a lawful import, and check hardlinks. Respect tracker seeding rules.
    
      
    
      
    VPN profile preparation & limitations
    Proton: export a Linux WireGuard profile for a P2P-capable server. Enable NAT-PMP in the export if your plan supports forwarding. Gluetun chooses a Proton endpoint in your selected country; it is not pinned to the file's endpoint.
    Other WireGuard providers: supply a standard Interface/Peer export with a literal-IP endpoint. The installer imports keys and addresses, not wg-quick hooks; Gluetun owns DNS/routing.
    OpenVPN: use a self-contained export with inline certificates/keys and any provider-specific credentials in private files. External certificate paths, plugins and executable hooks are rejected.
    Other providers can use static forwarded ports. Dynamic forwarding is currently Proton-only. VPN routing covers peer downloaders, not indexer/Usenet traffic or the whole server. Check Gluetun health/public-IP logs and its kill switch before adding downloads. TUN must be available in your host or VM.

    Reruns, updates & recovery
    Reruns reuse saved choices and credentials. They do not reset app databases or silently change the app/VPN selection. Enabled Recyclarr sync continues to update the profiles it manages. Use the same installation path. Bind address, link host, local proxy settings, auto-updates and profile sync can be changed with flags; other reconfiguration is manual.
    A failed first install can be rerun. Do not delete state to regenerate credentials for existing apps. Back up configs and databases; RAID is not a backup. Image updates are not automatic rollbacks, and stopping containers does not remove a managed cron updater.
